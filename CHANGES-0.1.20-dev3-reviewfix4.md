# Изменения 0.1.20-dev3-reviewfix4 (P0: «два окна»)

База: reviewfix3-cpufix. Один изменённый продуктовый файл: `valvebench/ui.py`
(класс App, +30 строк). Диф: `verification/fix3-to-fix4-ui-app-singlewindow.patch`.

## Дефект

Повторный запуск ValveBench (`./run.sh`, лаунчер) при уже открытом приложении
добавлял НОВОЕ окно вместо показа существующего: второй запуск — 2 окна,
третий — 3. Воспроизведено на изолированном стенде (свой D-Bus + Xvfb,
`verification/test_single_window_e2e.sh`): окна 1 → 2 → 3 → (после закрытия
всех) 1.

## Причина

`GApplication` с фиксированным `application_id="local.valvebench"` — один
экземпляр на сессию D-Bus. Повторный запуск становится remote-клиентом,
пересылает сигнал `activate` работающему процессу и завершается. Обработчик

```python
self.connect("activate", lambda a: Window(a).present())
```

создавал новый `Window` на КАЖДЫЙ сигнал, включая пересланные от remote-запусков.

Сопутствующий фактор той же природы: в системе 27 копий ValveBench разных
версий с ОДНИМ `application_id` — запуск любой копии при работающей другой
активирует работающую (подробности и рекомендация — в отчёте приёмки).

## Исправление

Класс `App` хранит единственное окно:

* `_on_activate`: окно создаётся только если `self._window is None`, иначе —
  только `present()` существующего;
* `close-request` окна сбрасывает ссылку (`self._window = None`) и возвращает
  False — штатная очистка `Window.on_close` (остановка аудиопотока,
  AnalysisWorker, сохранение калибровки и настроек) не затронута;
* `application_id` не менялся (настройки хранятся в `~/.config/valvebench/*.json`,
  от id не зависят; смена id потребовала бы синхронизации .desktop-файлов —
  решение за координатором, см. отчёт).

Регрессии после изменения: selftest **96/96**, приёмочный блок **11/11**,
compileall OK. DSP-наборы не затрагивают ui.py (110/26 оставались зелёными
на fix3; изменение изолировано классом App).

Замечание о моей вине в части симптома: инструментальный пробник
`gui_live_probe.py` подключал собственный activate-хендлер рядом с лямбдой
App, и оба создавали окно — при профилировании на рабочем столе появлялись
два окна за ОДИН запуск. Пробник переведён на окно App (сам дефект продукта
независим и воспроизводился обычным `./run.sh` без пробника).
