# CHANGES 0.1.12-p1 — P1: io_health (достоверность ввода/вывода steady)

Задание координатора после принятия P0 как контрольной точки. База — замороженная
`ValveBench-0.1.12-p0`; 0.1.11 и p0 не изменялись. Патчер `patch_p1.py` идемпотентен
(проверка new предшествует old) и воспроизводит пакет из свежей копии p0, включая
новый модуль `io_health.py`. Каноническая копия этого файла — `audit-steady/`.

## Четыре функции

### 1. XRUN-контроль
* stderr aplay и arecord пишется во **временные файлы** (pipe исключён — блокировка
  при любом объёме сообщений невозможна по построению; проверено сценарием 1,1 МБ).
* `scan_xrun_stderr()` считает underrun/overrun раздельно, хранит до 20 исходных
  строк (флаг усечения) и объём stderr; `xrun_summary()` агрегирует оба процесса.
* В `steady.json`: `io_health.xrun.{playback,capture}` + `total_xruns` + note о том,
  что отсутствие XRUN-сообщений не доказывает отсутствие всех аппаратных сбоев.

### 2. Контроль длины записи
* `length_status()`: фактические кадры против ожидаемых, отклонение в кадрах и мс,
  классификация ok/short/long при допуске ±50 мс (LENGTH_TOL_MS). Прежний жёсткий
  порог «запись короче программы» сохранён.

### 3. Фактическое начало воспроизведения (onset)
* Не порог по амплитуде: когерентная амплитудная кривая тона (окна 50 мс/шаг 25 мс)
  и **подгонка фазы известной трапеции огибающей** из `_write_test_program()`
  (замкнутая форма интеграла рампы), параболическое уточнение.
* Отдельно L (primary) и R (consistency): рассогласование >0,1 с обесценивает
  обнаружение. Надёжность: SNR тона над фоном ≥26 дБ, остаток фита ≤0,15,
  |сдвиг| ≤1 с. **Мёртвая зона 0,05 с**: внутри неё диапазоны не сдвигаются —
  окно анализа целиком остаётся в рабочем участке, и метрики не меняются.
* В `steady.json`: `io_health.onset` — измеренный onset, отклонение, SNR/остаток
  по каналам, reliable/applied/offset_s.

### 4. series_level_valid
* Теперь: уровни ∧ нет XRUN ∧ длина в допуске ∧ надёжное выравнивание.
* `validity_reasons[]` — причины по отдельности; пустой список = полностью
  достоверная серия. Применённая коррекция onset валидность не отнимает.
* `summary.txt` — блок «INPUT/OUTPUT HEALTH» и причины невалидности.

## Доработка onset (по ревью координатора перед приёмкой)

Три исправления, затронут только `io_health.py` (+ его тесты и None-безопасное
форматирование двух строк onset в summary — иначе требование «None при неудаче»
ломало бы отчёт; `steady.py` больше ничем не изменён):

1. **Симметрия раннего/позднего старта**: фон оценивается до самой ранней
   возможной рампы (t0 − ONSET_SCAN_S − 1.1…−0.05 с), опорная амплитуда полного
   уровня — после самой поздней (t0 + ONSET_SCAN_S + fade + 0.05…1.0 с); область
   анализа расширена. Раньше окна SNR загрязнялись самим искомым сигналом при
   сдвиге, близком к ±1 с.
2. **Граница диапазона поиска**: `search_boundary_hit` (минимум фита на крайнем
   узле сетки ±1 с) = ненадёжное обнаружение (прежде |tau| ≤ 1 с выполнялось всегда).
3. **Неизмеренное не выглядит измеренным**: при ненадёжном обнаружении
   `measured_onset_s = None` и `deviation_s = None`; ожидаемый момент — отдельно;
   диагностический tau остаётся в `confidence`.

Целевая таблица (selftest, сводный чек): −0,3/+0,3 → найдено точно и надёжно;
−0,8/+0,8 → надёжно; +1,2 → ненадёжно + search_boundary_hit + None; без тона →
None и SNR < 26 дБ; рассогласование L/R 0,3/0,5 → ненадёжно. E2E S8: сдвиг +1,2 с
→ серия невалидна, measured_onset_s = None.

## Диагностика right_channel_unverified (по ревью координатора)

* `detect_playback_onset()` возвращает `right_channel_unverified=True`, когда L
  обнаружен надёжно, а R не смог подтвердить onset (слишком короткая запись, мало
  окон, SNR ниже порога). Основной алгоритм не меняется: привязка по L остаётся
  рабочей, серия остаётся валидной; статус лишь фиксирует в JSON, что временная
  привязка подтверждена только по L. Рассогласование L/R (оба надёжны, τ
  расходятся >0,1 с) по-прежнему обесценивает обнаружение.

## Эквивалентность и тесты

* Selftest 0.1.12-p1: **58/58 PASS** (51 из p0 + 7 новых, включая целевую таблицу
  onset координатора и right_channel_unverified).
* Независимый набор (DSP + PCM): **38/38 PASS** против 0.1.12-p1.
* End-to-end на фейковых aplay/arecord: **8/8** (нормальный; +0,3 с с коррекцией;
  +0,02 с мёртвая зона; короткая запись; XRUN 5+2; stderr 1,1 МБ; реальная запись —
  аномальный E-MU 176,4 к 8/8 полей; +1,2 с → граница поиска).
* p0 ↔ p1: **0 несовпадений** в 31 метрике (синтетика 192 к/124 с и реальная запись).
* Peak RSS p1: 359–364 МБ (124 с @192 к) — без регрессии к p0.
