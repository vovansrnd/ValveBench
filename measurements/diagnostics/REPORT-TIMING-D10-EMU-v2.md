## 4. In-stream тишина после тона: 0 / 0.6 / 1.5 с (§11.5.5)

| Trailing | RMS после тона +0.4 с (R) |
|---|---|
| 0 | −44.6 (маркер Б в окне) |
| 0.6 | **−81.3** |
| 1.5 | **−80.8** |

**D10 честно воспроизводит тишину в потоке** — послетоновая зона уходит на
уровень остаточного шума (−81), тон не продлевается. Утверждение v1 о
«подмене тишины тоном» — отозвано (артефакт багов v1).

Что остаётся верным по остатку: ПОСЛЕ остановки потока (aplay закрыт) D10
продолжает излучать остаток последнего тона — измерено прямым демодуляционным
захватом: 1 кГц −89.9 dBFS L при закрытом потоке, RMS L −77.7 / R −83.4.
Этот после-потоковый остаток — вероятный источник «хвоста/затухания» на
хвостах длинных захватов, но он лежит ЗА ПРЕДЕЛАМИ поданных сэмплов и не
портит окно анализа, если окно привязано к маркерам.

## 5. L/R асимметрия и 300 Гц (§11.5.6) — источник НЕ назначен

| Конфигурация | RMS L | RMS R | 300 Гц L/R | 1 кГц L/R |
|---|---|---|---|---|
| E-MU capture, D10 idle (поток закрыт) | −77.8 | −93.7 | −130.9/−149.3 | −93.7/−109.8 |
| E-MU capture, D10 играет ноль | −77.7 | −83.4 | — | — |
| E-MU сама по себе (вчерашняя батарея) | −109.5 | −109.5 | — | — |

Асимметрия ~16 дБ присутствует при idle-D10 — но D10 физически подключён
(кабель + земля). Различить «D10 L-выход шумит» и «E-MU L-вход (ручка
усиления на передней панели)» без отцепления кабеля нельзя. **Требуемый
контроль: отсоединить кабель D10→E-MU от входов E-MU и повторить
E-MU-only захват.** (Вчерашнее «D10 вносит шум L>R» — преждевременный вывод,
отзываю; вчерашний замер E-MU −109.5/−109.5 сделан ДО подключения D10, когда
и усиление входов могло быть другим.)

## 6. Почему THD+N у координатора был 6–9 % (сведение)

Онсет-детектор срабатывает на клике открытия захвата / пред-тоновом остатке
D10 (0.775 с), реальный тон начинается ≈1.85–2.0 с (задержка 0.5 + позиция
0.5+1.26 с). Окно (onset+0.5, 4 с) включает ~0.8 с доволновой зоны с полом
D10 (−77/−81 дБФС) вместо тишины → THD+N завышен. Сам тон чист и заканчивается
вовремя (маркер Б ±50–230 мкс). Дрейф 24 ppm — независимый фактор когерентной
оценки гармоник (продукт сам честно метит «сдвиг бина»).

## 7. Рекомендация (не реализована, на решение)

Привязка окна анализа к маркеру/кросс-корреляции с поданной программой
(маркерный вариант проверен этим пробником на реальном железе: corr 0.996,
одиночные пики, ±50 мкс). Регрессионные случаи для будущего фикса:
tone-only, multi-segment, clock-drift, click/noise, DUT-response — по списку
координатора.

## 8. Артефакты (все закоммичены)

`timing-v2-baseline-2s.json` (+raw-захват), `timing-v2-dur-{1,2,5,10}s.json`,
`timing-v2-trail-{0,0.6,1.5}s.json`, `controls-emu-only.txt`,
`timing-v2-baseline-2s-envelope.csv`, этот отчёт. Команды каждого прогона —
в JSON-поле «команда» дублируется в логе `timing-v2-run-log.txt`.

# Приложение v2.8 (13.11.2026) — joint-LSQ на восьми захватах v2.7: декомпозиция плато

Инструмент: `verification/v28_offline_analysis.py` (§14.5.1-2: офлайн, без
железа, joint-LSQ 0.25 с / шаг 0.125 с, ОБА канала, частоты с измеренным
ppm: 996.977 Гц тон / 999.977 Гц остаток preflight).

## 1. 997-доминирующие регионы (A997 > A1000 + 6 дБ, уровень ≥ −45 дБФС)

| Условие | 997-доминирует | Длительность 997 | Подано тона | Потеря 997 |
|---|---|---|---|---|
| lead=0 ×4 | 1.00–4.75 с | **3.75 с** | 4.55 с | **~0.80 с** |
| lead=1.5 ×4 | 2.00–6.25 с | **4.25 с** | 4.55 с | **~0.30 с** |

## 2. Декомпозиция (§14.5.4 — «развести два эксперимента»)

* **lead=0**: потеря 997-тона ~0.80 с = голова (~0.45 с: старт рендера после
  чирпа... программа начинается тоном с сэмпла 0 — теряется ГОЛОВА тона) +
  хвост (~0.35 с: рендер кончается раньше поданного конца).
* **lead=1.5**: потеря 997-тона ~0.30 с = **только хвост** (~0.35 с): голова
  съедена лидирующей тишиной ✓ (модель v2.7 для головы подтверждена), но
  хвостовое усечение ~0.3–0.35 с ОСТАЁТСЯ во всех четырёх lead=1.5 прогонах.
* Разъяснение прежнего противоречия: плато v2.7 4.5413 с «выглядело полным»
  (4.55 − 0.009), потому что включало **0.2 с остатка preflight** перед тоном
  (env997 выше −45 на реплике 1 кГц) и теряло ~0.3 с хвоста — две ошибки
  компенсировались. joint-LSQ (частотно-селективный) их разделяет.

## 3. Следствия для production-меры

1. Лид-тишина 1.5 с закрывает только головную потерю (~0.5 с).
2. **Хвостовое усечение ~0.3–0.35 с требует отдельной меры** — защитный
   хвост ≥0.6 с после тона (реплика хвоста = тишина подтверждена: послетон
   −81 дБФС в v2.7).
3. Production-окно 4.0 с при плато 4.25 с (lead=1.5) всё ещё вылезает на
   ~0.3 с → THD+N 1.0–1.15 % (L) содержит хвостовое загрязнение. Для чистого
   результата: либо окно короче, либо хвост длиннее.
4. Уровни −45/−55/−65 дБФС: обрыв жёсткий (45→54→77 дБФС за 40 мс на 4.88–5.0 с).

## 4. Ограничения

* Разрешение joint-LSQ 0.25 с → границы ±0.25 с; точные кадры обрыва требуют
  короткого окна (жёсткий обрыв виден на 2-мс огибающей: 4.88–4.90 с).
* Данные: `v26-ab/v28-offline-analysis.json` (профили всех 8 захватов,
  оба канала); команды/stderr per-run — в `v26ab-summary.json` (observer).
