# Отчёт: посемпловая характеристика D10 → E-MU (ТЗ §8 выполнена)

Дата: 12.11.2026. Инструмент: `verification/timing_probe.py` (этот коммит).
Метод: маркерная программа (тишина 1 с → маркер 6.5 кГц 60 мс → тон 997 Гц →
маркер 8 кГц 60 мс → тишина 1 с), arecord стартует заранее на +3 с, маркеры и
тон находятся узкой демодуляцией с адаптивным порогом, отдельно L/R.
Карты автодетектом по USB-ID (за сессию они менялись дважды; в последних
прогонах D10 = card2, E-MU = card3). Уровень тона −30 dBFS, S32_LE playback
(DX1-опыт показал, что S24_3LE есть не у всех ЦАПов — D10 поддерживает).

## 1. Ответы на вопросы ТЗ (§8, objective)

**Q1: все ли сэмплы, поданные в aplay, выходят из D10?**
ДА — и даже больше: тон на выходе **длиннее** поданного. Захваченная
длительность тона = поданная **+ 0.425 с** на всех длительностях:

| Подано | Захвачено | Хвост |
|---|---|---|
| 1.000 с | 1.425 с | +0.425 |
| 2.000 с | 2.425 с | +0.425 |
| 5.000 с | 5.425 с | +0.425 |
| 10.000 с | 10.425 с | +0.425 |

**Q2: фиксированная стартовая задержка / фиксированное усечение хвоста?**
Стартовая задержка (по маркеру): 0.747–0.756 с, джиттер ~9 мс между запусками
(подрезка длины программы на 8 с дала сдвиг маркера 9 мс — стартовый джититер
открытия, не дрейф). Усечения НЕТ: тон не обрезается, а **удлиняется** на
фиксированные 0.425 с.

**Q3: длительность захваченного тона = поданной?** Нет: +0.425 с (см. выше).
Хвост не зависит от длительности — фикс-время, не пропорция и не дрейф
(24 ppm дали бы 0.0005 с на 2 с, не 0.425 с).

**Q4: зависимость от буферов ALSA / закрытия aplay?** Нет: буферы
50/100/200/400 мс дают один и тот же хвост +0.425 с (400 мс: L-канал
детектировался дольше из-за L-спура, R = ровно 2.425). Стартовая задержка
0.717–0.753 с слегка гуляет. Значит хвост — свойство D10 (прошивка/выходной
узел), не параметров ALSA.

**Q5: L/R шум и линия 300 Гц?** Подтверждено: **D10 L-выход шумнее R на
~16–17 дБ** на линиях (idle: 300 Гц L −110.5 / R −127.9; 1 кГц L −96.2 /
R −112.8; после стопа RMS L −77.7 / R −83.4). Линия 300 Гц во время
воспроизведения (−53.6 dBc L по данным координатора) появляется только при
активном потоке — в idle её нет; сильнее на L. Это свойства тракта D10, не
E-MU (E-MU сама по себе L=R=−109.5 дБФС).

**Q6 (модель хвоста, дополнительное открытие):** D10 **не воспроизводит
цифровой ноль честно**: если в потоке после тона идёт тишина, демодуляция на
997 Гц продолжает видеть тон сквозь неё. Добавление 0.6 с тишины в конец
потока продлило «видимый тон» на +0.64 с (тон конец = tone_end + 1.066 с
против +0.425 с без тишины). После остановки потока D10 продолжает излучать
остаток последнего тона (−90 дБФС L, измерено ранее и сейчас: RMS L −77.7 /
R −83.4 при полном молчании aplay). Т.е. D10 подменяет тишину последним
слышимым содержимым — это поведение прошивки, не ALSA.

## 2. Модель (объясняет все прогоны координатора)

1. **Клик открытия захвата** (E-MU arecord start, 0–0.5 с, RMS −58 дБФС) —
   на нём срабатывает широкополосный onset детектора → сохранённый
   «onset 0.775 с» — НЕ начало тона. Реальный тон в захвате начинается
   на ~1.85–2.0 с (задержка 0.75 с + позиция в программе 1.31 с).
2. Окно анализа (onset + 0.5 + 4 с) начиналось **~0.8 с раньше тона** —
   внутрь окна попадает доволновая зона с шумовым полом D10 (−77 дБФС
   широкополосно + остаточные линии) → завышение THD+N (6–9 %).
3. Конец тона в захвате = конец поданного тона + 0.425 с хвоста → окно
   почти всегда накрывало переход «тон → остаток» → дополнительный вклад.
4. Удлинение тона (run D, +0.6 с) сдвинуло конец тона за пределы окна →
   THD+N упал до 1.04 % (L) / 0.126 % (R) — окно целиком внутри тона.
5. Дрейф 24 ppm — независимый фактор (портит когерентную оценку гармоник),
   к таймингу отношения не имеет (0.0005 с на 4 с, не 0.4 с).

## 3. Предлагаемое исправление (на утверждение координатору, НЕ реализовано)

`Rig.run()` должен привязывать окно анализа к **реальному положению тона в
захвате** через кросс-корреляцию с поданной программой (программа известна
точно): взять 0.5-с кусок тона из программы, найти его в захвате
кросс-корреляцией — координата даёт начало тона с точностью до сэмпла,
иммунно к клику открытия, остаткам D10 и джиттеру задержки. Окно анализа =
найденное начало тона + settle-смещение, с контролем: (окно + запас 0.3 с
с обеих сторон) ≤ конец захваченного тона. Узкополосный onset остаётся
fallback'ом. Это закрывает критерий ТЗ «окно доказуемо целиком внутри
стабильного тона».

## 5. Ограничения

* Маркер 8 кГц детектируется плохо на фоне 997 (H8 тона = 7976 Гц) — в
  отчёте конец тона брался по демодуляции 997 Гц; для будущих прогонов
  маркер конца стоит выбрать ≥11 кГц.
* L-канал D10 периодически детектируется «дольше» (спур) — числа R надёжнее.
* Замер «пола линии» целиком (включая края потока) завышается
  старт/стоп-транзиентами; для честного пола нужна середина записи.
