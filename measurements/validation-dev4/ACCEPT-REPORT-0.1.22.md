## 3. Прямая петля D10→E-MU (§3) — ВЫПОЛНЕНО (10.11, после подключения D10)

Оборудование: **SMSL D10** (152a:85dd, Thesycon) = card3, **только playback**
(hw:3,0; S16/S24_3LE/S32/DSD, 44.1–384 кГц); E-MU 0404 USB = card2, capture

перечитаны заново (devices-after-d10.txt).

**Безопасность уровня** (протокол координатора): первый сигнал 1 кГц −40 dBFS →
АЦП −53.2/−52.9 dBFS, пик 0.005, CLIP нет; далее −30 dBFS → АЦП ≈ −37.5 dBFS.
Phantom/усиление не трогались.

**Шумовой пол линии (ключевая находка):** при подключённом D10 (поток закрыт)
пол линии = **−77.4 dBFS** (20 Гц–20 кГц) против −109.5 dBFS у E-MU самой по
себе — на 32 дБ выше. Состав: широкополосный шум + остаточные линии 1 кГц/
750/1500/2000 Гц (следы последнего воспроизведённого сигнала — D10 не мьютит
выход сразу после остановки потока; флеш цифровым нулём пол не убирает).
Следствие: штатный preflight −72 dBFS (тон на АЦП ≈ −79) физически ниже пола
линии → onset невозможен. Это свойство маршрута, не дефект детектора.

**Clock drift между независимыми тактами (п.3 задания):**

| Частота | Прогоны | ppm (L/R) | Холодный старт |
|---|---|---|---|
| 48 кГц | **10/10 PASS** | −23.9…−24.4 (разброс 0.5) | включён, PASS |
| 96 кГц | 3/3 PASS | −23.6…−24.7 | PASS |
| 192 кГц | 3/3 PASS | −24.3…−24.6 | PASS |

**Такт D10 стабильно ниже такта E-MU на ≈24.3 ppm** на всех частотах,
ворота 100 ppm пройдены с запасом ×4. WAV+JSON каждого прогона:
d10-clock-*-runNN.wav/.json (16 прогонов).

**Реакция на >100 ppm (п.4):** искусственные +976 ppm (программа 1001 Гц
против номинала 1000) → ворота сработали на обоих каналах («ПРЕВЫШЕНИЕ
ОБНАРУЖЕНО»), измерение корректно отказано. Базовая линия на реальных тактах
в том же прогоне: −24.2/−24.1 ppm → в норме. PASS.

**THD+N/спектр/остаток на −30 и −40 dBFS (п.5):**
* −30 dBFS: АЦП −37.4 dBFS; THD+N 9.15 % (−20.8 dBc), остаток −58.2 dBFS;
* −40 dBFS: АЦП −47.5 dBFS; THD+N 10.1 % (−19.9 dBc), остаток −67.4 dBFS;
* **Интерпретация:** эти числа НЕ являются искажениями тракта. На паре с
  дрейфом 24.3 ppm когерентный оценщик уводится утечкой: продукт сам честно
  помечает «сдвиг тона ±0.03 бина превышает допуск» (ворота когерентности
  работают на реальном дрейфе — положительный результат приёмки). Спектр:
  тон 997 Гц −38.5 dBFS, сеть 60 Гц −88.3, остальное — пол линии.
  Вывод: для точного THD+N на разделённой паре нужен либо источник с тактом
  ≤1 ppm от АЦП, либо некогерентный режим (§6 задания — вне этой приёмки).

**Наблюдение для пользователя:** зависимость уровень-генератора → уровень-АЦП
нелинейна (−40 → −53.2 дБФС, но −30 → −37.5 дБФС: 10 дБ команды дали 15.8 дБ
на АЦП). Проверь собственную громкость/гейн D10 — возможно, у него активная
регулировка выхода.

## 5. Найденные и исправленные дефекты (продукт dev4)

**D1. `cli.py`: UnboundLocalError на всех точных командах.**
Вложенная `def make_rig(fs)` (строка 284, ветка passport/watch/psdcheck)
затеняла модульную `make_rig(a)` для всей функции `main()` — команды, идущие
через нижний диспетчер (`clock`, `loopback`, `thd`, `thdlevel`, `sweep`, …),
падали `UnboundLocalError` ДО открытия устройства. Исправлено переименованием
внутренней функции в `make_rig_pair` (3 использования). Блокировало всю
аппаратную приёмку через CLI.

**D2. `gainmatch.py`: отпечаток микшера включал летучие PCM-элементы.**
`mixer_fingerprint_from_hw` хэшировал весь `amixer contents`, включая
`iface=PCM 'Capture Channel Map'`, значения которого меняются при
открытии/закрытии PCM (0,0 → 3,4 на E-MU). Результат: эталон петли
отвергался при ПЕРВОЙ же повторной проверке без каких-либо изменений
микшера (воспроизведено диффом amixer открыт/закрыт). Исправлено: хэшируются
только `iface=MIXER`-блоки (`_mixer_only_blocks`); стабильность проверена
на открыт/закрыт. После фикса весь сценарий референса — PASS.

**D3. `measure.py`: узкополосный onset отвергал настоящий тон из-за щелчка
открытия.** Холодный отказ clock-теста (координатор: «не списывать на
случайность») воспроизведён систематически: циклы «простой 60 с → запуск»

`np.percentile(blocks, 99)`; отказовая запись сохранена как регрессионный
ассет `verification/data/cold-fail-dlx-96k.npy`, тест
