# ValveBench 0.1.20-dev3 — review fixes

Эта сборка — адресный review-патч поверх пользовательского архива `ValveBench-0.1.20-dev3.tar(1).gz`.
Это не объявление официального dev4/stable-релиза. Версия приложения сохранена.

## Исправления

### Peak Hold / АЧХ по пластинке

- Когерентные оценки переходного затухания L→R и R→L накапливаются раздельно по каждому частотному бину. Смена ведущего канала больше не смешивает два физических направления в одну комплексную сумму.
- Направление ведущего канала сохраняется в `Overlay`, JSON и CSV. В представлении переходного затухания используется направление конкретной полосы; старые сохранённые кривые без поля `driven` остаются совместимыми и используют прежнюю оценку по медиане.
- Нормировка «0 дБ на 1 кГц» теперь интерполируется по логарифму частоты. Если 1 кГц вне диапазона реально накопленных данных, ближайшая полоса не выдаётся за 1 кГц: кривая остаётся ненормированной, а CSV явно помечает отсутствие опорной частоты.
- Для стерео-свипа с пересечением АЧХ каналов смена ведущего канала по частоте не классифицируется как один канал плюс утечка; нормировка каналов остаётся независимой.
- При смене разрешения полосы перестраивается и массив поправки АЧХ, поэтому размеры аккумулятора и коррекции совпадают.
- Перед Save заново считывается отпечаток ALSA-микшера. Если он отличается от контекста накопления, текущая кривая сбрасывается и не сохраняется как единая запись из двух разных условий.
- Предупреждение о несовпадении сохранённых кривых учитывает карту, Fs и микшер.
- CSV рассчитывает переходное затухание по тем же скорректированным уровням L/R, которые экспортируются в столбцы.

### Glitch / целостность аудиозаписи

- Длительные провалы несущей восстанавливаются по непрерывной огибающей 1 мс; фрагменты, пересекающие границы блоков, объединяются. Проверены провалы 0,3 / 2 / 4 с на двух положениях относительно 2,7-секундной границы.
- Для полностью отсутствующей контрольной несущей отчёт теперь говорит, что проверка провалов недостоверна, вместо ложного «0 провалов».
- Повторно используется огибающая, уже рассчитанная `frame_integrity`; отдельный демодулятор повторно не запускается для каждого штатного блока.
- Флаг `--keep-wav` передаётся в потоковый анализ и действительно создаёт float32 WAV.
- Весь путь захвата/анализа защищён `try/finally`: временные raw-файлы удаляются и при исключении во время захвата или создания источника.
- Документация и тест больше не обещают строго постоянную память: PCM читается блоками, но для длительных провалов хранится огибающая с шагом 1 мс (ориентировочно около 20 МиБ на 10 минут для двух ведомых каналов, без учёта временных массивов).

## Совместимость

- Старые JSON-кривые без поля `driven` загружаются; для них применяется старое глобальное определение ведущего канала.
- Новые кривые сохраняют направление для каждой полосы.
- Формат приложения/версия не менялись.
