# ValveBench
> **Выбор аудиоустройства.** По умолчанию приложение запускается на симуляторе, а не на случайной ALSA-карте. В списке показываются только устройства, у которых обнаружены и playback, и capture. На системе, где E-MU отображается как `card 2`, выбирай `hw:2,0`. Номер ALSA-карты может меняться; ориентируйся на имя E-MU в списке, а не копируй номер с другого компьютера. HDMI-only выходы не предлагаются как измерительные устройства.

 0.1.1

Измерительная лаборатория для разработки и настройки аналоговых аудиотрактов, прежде всего ламповых фонокорректоров. Linux / Ubuntu, Python, GTK4 + Libadwaita.

Это первая самостоятельная версия третьей ветки. Она не является завершённым или метрологически аттестованным прибором. DSP проверяется на известных синтетических сигналах и виртуальном DUT; реальные показатели E-MU 0404 USB или ASUS Strix Raid DLX нужно проверить на рабочем компьютере.

## Установка и первый запуск

Из каталога проекта:

```bash
./install-deps.sh
./run.sh selftest
./run.sh debug
./run.sh
```

`install-deps.sh` использует системные пакеты Ubuntu. Программа не использует Wine, Java, Electron или PortAudio. Аппаратный ввод/вывод в этой версии идёт через ALSA `aplay`/`arecord`.

`run.sh` выбирает системный `/usr/bin/python3`, когда в нём доступны NumPy, SciPy и GTK bindings. Иначе использует `python3` из `PATH`, что позволяет запускать CLI/self-test из научного venv. Для явного выбора интерпретатора задайте `VALVEBENCH_PYTHON=/путь/к/python ./run.sh`. Для GUI выбранный Python должен видеть совместимые GTK4/PyGObject bindings.

## Первый запуск без звуковой карты

В заголовке GTK-окна выберите «Симулятор (демо без карты)» и нажмите «Живой режим». Это виртуальная модель с RIAA, шумом, сетевым фоном и нелинейностью. Симулятор предназначен для проверки интерфейса и алгоритмов, а не для демонстрации качества реального фонокорректора.

Проверки математического ядра:

```bash
./run.sh selftest
./run.sh cli --sim --rate 48000 thd --f 1000 --level -24
./run.sh cli --sim --rate 48000 sweep --mode riaa --dur 4 --level -30
./run.sh cli --sim --rate 48000 noise-response --kind pink --seconds 4 --level -42 --hi 16000
./run.sh cli --sim --rate 96000 imd --preset 'CCIF 19+20 кГц'
```

## Аппаратный запуск

Список карт и режимов:

```bash
./run.sh cli cards
```

Выберите карту `hw:N,0` в шапке приложения и частоту дискретизации. Для E-MU 0404 USB обычно нужно выбирать аналоговую пару каналов в `in_map`/`out_map`; цифровые S/PDIF-каналы могут идти следующей парой.

Проверка фактического такта loopback (нужно физически соединить DAC с ADC подходящим кабелем и уровнем):

```bash
./run.sh cli --dev hw:2,0 --rate 96000 clock
```

Не подключайте выход ЦАП непосредственно ко входу фонокорректора без рассчитанного аттенюатора. Вход MM обычно требует корректного сопротивления и ёмкости нагрузки. Защитите ADC от перенапряжения и проверьте входные уровни перед длительными измерениями.

## Основные приборы

- **Gain Match / Уровень** — два вертикальных RMS-индикатора рядом, Peak, Peak Hold, CLIP, цифровой уровень, физические напряжения и разница усиления L−R. Вольты и усиление отображаются только после независимой калибровки DAC L/R и ADC L/R.
- **THD / THD+N** — отдельные гармоники, THD, THD+N, фон сети и THD в зависимости от уровня.
- **АЧХ / RIAA / Sweep** — экспоненциальный свип Фарины, inverse-RIAA или плоский сигнал, отклонение от RIAA и THD(f).
- **АЧХ шумом / H1** — белый, розовый или inverse-RIAA-shaped шум. Известный сигнал ЦАП сравнивается с записью по H1 = Sxy/Sxx; coherence показывается отдельно. Есть одноразовый и живой режимы. Это не обычный RTA-спектр выхода.
- **IMD** — CCIF 19+20 кГц, SMPTE/DIN и настраиваемые пары тонов.
- **Шум / Crosstalk** — невзвешенный, A/C-взвешенный шум, спектральная плотность, фон и электрическое проникновение каналов.
- **TACET / Vinyl Test** — анализ WAV-записей A2/A3/A4/A5/A6/A7 и автотрекинг частотных ступеней B2. Ограничения методов см. `docs/TACET.md`.

## Шумовая АЧХ: что именно измеряется

Шумовой тест строит передаточную функцию `H1(f)=Sxy(f)/Sxx(f)` из известного тестового сигнала `x` и записанного сигнала `y`. Это позволяет измерить относительную передаточную характеристику, даже если точный момент старта неизвестен. Coherence показывает, насколько хорошо выход связан с тестовым сигналом.

В результат попадают **весь** тракт: ЦАП, внешний делитель/аттенюатор, DUT, АЦП и соединения. Без калибровки петли ЦАП→АЦП программа не может отделить частотную характеристику фонокорректора от характеристики измерительной карты. Поэтому график подписан как относительный; не следует считать его лабораторной точностью только потому, что он гладкий.

Белый шум имеет примерно равную спектральную плотность на герц; розовый — примерно равную энергию на октаву. Inverse-RIAA-shaped noise предварительно формируется так, чтобы после исправной RIAA-коррекции выход был приблизительно ровным. Для каждой полосы важны уровень, отсутствие перегрузки и coherence.

Для точной проверки АЧХ сохраняется и ступенчатый синус/свип: шумовой метод удобен для быстрого наблюдения, но не заменяет все установившиеся измерения.

## Калибровка

На вкладке Setup калибруются независимо:

1. DAC L и DAC R — мультиметром при 1 кГц и −6 dBFS.
2. ADC L и ADC R — петлёй DAC→ADC без внешнего аттенюатора.
3. Внешний аттенюатор DAC→DUT указывается отдельно в dB.

До калибровки корректно показывать dBFS и относительные величины. Физические вольты и gain не должны подменяться выдуманными значениями.

Калибровка ADC loopback не измеряет THD/IMD самого ЦАП/АЦП и не удаляет его частотную характеристику. Для качественной оценки самого фонокорректора нужен также loop-профиль по частоте; его отдельная калибровочная процедура будет следующим этапом.

## Текстовая диагностика вместо скриншотов

При проблеме не нужно снимать скриншоты. Запустите:

```bash
./run.sh debug
```

Команда печатает текстовый отчёт: ОС, ядро, Python, наличие GTK/пакетов, ALSA-карты, объявленные частоты/каналы, активные `hw_params`, доступность `aplay`/`arecord`, сводку калибровки и результат self-test симулятора.

Для сохранения отчёта:

```bash
./run.sh debug --save
```

Файл попадёт в `~/.local/state/valvebench/debug/`. Можно прислать весь вывод команды или содержимое TXT. `debug` **не открывает звуковые устройства и не запускает звуковой сигнал**.

Дополнительно:

```bash
./run.sh debug --no-selftest   # короткий отчёт без прогонов DSP
./run.sh cli cards             # список ALSA-карт
./run.sh cli --dev hw:2,0 --rate 96000 clock   # отдельная проверка физического loopback
```

Если проблема возникает именно при открытии окна или работе интерфейса, запустите его с записью терминального вывода:

```bash
./run.sh 2>&1 | tee ~/valvebench-gui-log.txt
```

При ошибке можно прислать текст из терминала или этот TXT. Скриншоты не нужны.

Команды аппаратного измерения требуют работающей карты и правильного соединения. Они выполняются с ограниченными таймаутами; программа должна завершаться с текстовой ошибкой, а не ждать бесконечно.

## Сохранение

Настройки и калибровка: `~/.config/valvebench/config.json`.

Результаты JSON: `~/.local/share/valvebench/`.

## Известные ограничения этой версии

- GTK-интерфейс написан под GTK4/Libadwaita, но в среде сборки не было PyGObject и звуковой карты; здесь он проверен статически, а не запущен на рабочем Ubuntu.
- Аппаратный ALSA backend не проверен на вашей E-MU и ASUS. Сначала необходимы `debug`, `cli cards`, затем контролируемый loopback.
- В этой версии `wow_flutter_unweighted` — необвешенная оценка нестабильности 3150 Гц, а не стандартизованный DIN/IEC Wow & Flutter.
- TACET B2 использует автотрекинг синусных ступеней с окном 1 с / шагом 0,25 с; короткие ступени могут быть пропущены. Точные уровни записи и таблица допусков не предоставлены.
- TACET-анализ — диагностика по записанному WAV, не сертифицированная оценка проигрывателя или картриджа.
- Нет автоматической калибровки частотного отклика всей звуковой карты; точные абсолютные выводы о DUT пока преждевременны.
- Запись с LP включает проигрыватель, картридж, тонарм, кабель, фонокорректор и ADC; результат нельзя приписать одному фонокорректору.
