# ValveBench 0.1.21-dev4 — раздельные ЦАП/АЦП

## Что нового в 0.1.21-dev4

- В GUI и CLI отдельно выбираются ALSA PCM воспроизведения (ЦАП) и записи (АЦП). Старый `--dev` оставлен как совместимый выбор одного endpoint для обеих сторон.
- `aplay` открывает выбранный ЦАП, `arecord` — выбранный АЦП; форматы playback/capture согласуются независимо.
- Для точных измерительных алгоритмов с общей временной сеткой частота пока **одна на пару**: список режимов строится по пересечению объявленных частот ЦАП и АЦП. Независимые Fs и асинхронный ресэмплинг не включены.
- Перед измерениями на разных устройствах выполняется clock preflight тоном −72 dBFS по умолчанию. Проверка раздельно показывает расхождение тактов, локальный SNR контрольного тона, согласие оценок L/R и когерентность FFT-окна; при локальном SNR ниже 20 дБ, разбросе L/R более 5 ppm или расхождении более 100 ppm измерение отклоняется. Уровень не повышается автоматически: явный `--clock-level` используйте только после проверки безопасного уровня в физическом тракте.
- Тоновые THD и IMD анализируют мощность отдельных блоков и не теряют сигнал из-за фазового вращения между блоками. Для Farina sweep и H1 noise-response измеренный clock preflight коэффициент используется для ресэмплинга захвата на временную сетку источника до деконволюции/оценки H1. Поправка сохраняется в результате как `clock_correction_ppm`, вместе с полным протоколом `clock_check` по каналам L/R; это коррекция записи, а не синхронизация самих USB-устройств.
- Калибровочные профили и Gain Match loopback-привязки относятся к полной паре DAC→ADC. Изменение одного из микшеров делает старый loopback-эталон недействительным.
- Паспорта тракта явно записывают `dac_device`, `adc_device` и раздельные форматы/число каналов.

Пример: D10 как источник, E-MU как измерительный вход (подставь актуальные номера из `devices`):

```bash
./run.sh cli devices
./run.sh cli --dac hw:3,0 --adc hw:2,0 --rate 192000 thd --f 997 --level -12
./run.sh cli --dac hw:3,0 --adc hw:2,0 passport --rates diagnostic --label d10-emu --out measurements/d10-emu.json
```

`192000` здесь допустимо только если обе стороны объявляют этот режим и точно открываются. Если общей частоты нет, надо использовать режимы `steady`/`glitch` с собственным измерителем и параметрами `--play-dev`/`--rec-dev`, а не подменять общую Fs. `stream0` — только подсказка возможностей; реальное открытие ALSA остаётся окончательной проверкой.

**Ограничение:** два USB-устройства имеют независимые часы. Clock preflight измеряет разницу частот, но не синхронизирует устройства. Для sweep/H1 сейчас применяется одна статическая поправка, измеренная перед тестом; предполагается, что отношение частот ЦАП/АЦП остаётся стабильным в течение записи. Непрерывное слежение за изменяющимся дрейфом и аппаратная синхронизация не реализованы. Граница допуска коррекции — ±100 ppm; при плохом SNR, перегрузке или несогласии оценок L/R измерение отклоняется.

**Проверки dev4:** 106/106 DSP selftest, плюс независимые тесты ALSA endpoints, clock preflight, миграции старой конфигурации, Gain Match pair-reference и UI source contracts. В среде сборки нет GTK/PyGObject и физического D10/E-MU: GUI и реальное оборудование здесь не принимались.


Паспорта DUT и экспорт результатов одного/пакетного измерения сохранены из dev1/dev2. Подробности: [экспорт измерений DUT](docs/DUT-MEASUREMENT-EXPORT.md), [калибровка и PAD](docs/MEASUREMENT-CALIBRATION.md), [изменения предыдущих шагов](CHANGES-0.1.21-dev1.md).

Историческое описание интерфейса и калибровочная документация ниже относятся к предыдущим версиям; синтетические результаты не являются характеристиками физической звуковой карты.
Начни с `./run.sh selftest`, затем `./run.sh debug`.

Профили идентичности `installed`/`development` и настройка `application_id` описаны в [docs/BUILD-PROFILES.md](docs/BUILD-PROFILES.md). Dev-архив уже помечен как `development`; для постоянной установленной копии используй `./tools/set-build-profile.sh installed`.

## Что нового в 0.1.16

- **АЧХ по умолчанию — обычная плоская развёртка и нормированная на 1 кГц характеристика L/R.** RIAA и RIAA+IEC не выбираются автоматически; это отдельные режимы для проверки фонокорректора. Выбранные пользователем настройки сохраняются.
- **Калибровка АЧХ/фазы измерительной карты** выполняется по прямой петле ЦАП L→АЦП L и R→АЦП R. Поправка хранится отдельно для физической карты и частоты дискретизации, применяется к каналам независимо и не экстраполируется за измеренный диапазон.
- Профиль карты автоматически активируется после выбора этой карты. Для USB-карты без серийного номера используется VID:PID, если устройство уникально; если подключены две одинаковые карты, для различения используется USB-порт. Поэтому перенос уникальной карты в другой разъём не теряет её профиль.
- В настройках есть отдельные переключатели автоматического применения поправки АЧХ/фазы и отображения шумового пола. Выключение показывает сырые данные ЦАП→DUT→АЦП.
- После калибровки проверяется совпадение ALSA-микшера. Если громкость, источник или другой параметр микшера изменился, старая поправка не применяется до повторной калибровки.
- **Шумовой пол АЦП** измеряется отдельно при нагруженных/замкнутых входах, сохраняется для физической карты и Fs и отображается одной и той же измеренной плотностью в Спектре, THD и IMD. В графиках с dBFS/bin плотность пересчитывается в ENBW; у IMD учитывается усреднение блоков. Это ориентир собственного шума карты, а не шум DUT.
- Стартовые цифровые уровни стали практичнее: синус THD/генератора и сумма IMD — −6 dBFS; шумовой тест — −12 dBFS RMS с ограничением пика −3 dBFS. Значения регулируются и сохраняются. Миграция меняет только прежние заводские значения, пользовательские значения сохраняются.
- FFT по умолчанию — 256k для лучшего частотного разрешения; пользовательский размер FFT сохраняется.
- Небольшие численные остатки около нуля в АЧХ округляются до точного нуля при вычислении и отображении.
- THD, IMD, crosstalk, clock и аудиопоток получили более понятные названия действий и разъяснения. Crosstalk показывает численные L→R/R→L результаты на 100 Гц, 1 кГц и 10 кГц рядом с графиком.
- В Setup явно показывается, активен ли профиль этой карты, отключено ли его автоприменение или состояние микшера требует повторной калибровки.

**Проверки этой сборки:** `./run.sh selftest` — 71/71 PASS; `python -m compileall -q valvebench` — без ошибок. В сборочной среде нет GTK/PyGObject и ALSA-устройств, поэтому визуальный запуск и реальные аппаратные измерения здесь не выполнялись.

## Что нового в 0.1.11

- `steady` отдельно контролирует присутствие основного тона короткими LS-оценками амплитуды: по умолчанию 10 мс при 997 Гц; для низких частот окно автоматически увеличивается, чтобы в нём было не менее пяти периодов.
- Потеря несущей выделяется отдельно от широкополосного остатка: эпизод фиксируется, когда уровень основного тона держится как минимум 20 мс не менее чем на 20 дБ ниже фактически измеренного стабильного уровня.
- Создаётся `tone-continuity.csv` с уровнем несущей каждые 10 мс (или с адаптивным окном для низких частот), относительным уровнем и номером подтверждённого эпизода.
- Измерительные окна `L_steady` и `R_steady` имеют защитные интервалы на краях (по умолчанию 250 мс, с учётом ширины окна). Это не сокращает воспроизводимый тестовый тон, а исключает возможное попадание fade-in/fade-out в steady-статистику.
- В `steady-compare` добавлены число эпизодов потери несущей и максимальная их длительность отдельно для L/R.
- Отчёт явно разделяет `residual excursions` и `carrier dropouts`: это разные явления, и одно не следует автоматически трактовать как другое.

## Выбор интерфейсов и измерение между картами

Посмотреть реальные номера ALSA PCM (они могут меняться после переподключения USB):

```bash
./run.sh cli cards
./run.sh cli devices
```

Пример: ЦАП на одной карте, АЦП на другой. Перед запуском подставь текущие `hw:C,D` из `devices`:

```bash
./run.sh cli --rate 192000 steady --play-dev hw:3,0 --rec-dev hw:2,0
```

Если простая карта поддерживает только 48 кГц, задай её частоту явно:

```bash
./run.sh cli --rate 48000 steady --play-dev hw:0,0 --rec-dev hw:2,0
```

`steady` по умолчанию выдаёт тон −18 dBFS и просит настроить выход до −23.4 dBFS на обоих
входах АЦП (допуск ±1 dB). Не используй проценты ALSA mixer как меру напряжения. После калибровки
не меняй регуляторы. По умолчанию тест содержит по 15 секунд тишины до и после, 8 секунд паузы
между каналами. Эти параметры меняются через `--idle-seconds` и `--gap-seconds`; уровень задаётся
через `--target`, `--tone-level`, `--tolerance`.

Для измерения карты самой на себя укажи один и тот же endpoint в обоих параметрах. Для отдельных
ЦАП и АЦП укажи разные. `--play-format auto` и `--rec-format auto` проверяют `S24_3LE`, `S24_LE`,
`S32_LE`, `S16_LE` по очереди и выбирают первый реально открывающийся вариант.


## Сводное сравнение нескольких измерений

После отдельных запусков `steady` можно вывести общую таблицу маршрутов (само измерение
всё равно выполняется отдельно для каждой физической пары: кабели вручную переставляются):

```bash
./run.sh cli steady-compare \
  emu_measurements/steady-20261102-161953 \
  emu_measurements/steady-20261102-162455 \
  emu_measurements/steady-20261102-162813 \
  --csv emu_measurements/steady-matrix.csv
```

В таблице остаются отдельные ЦАП→АЦП, уровни тишины, проникновение, остаток, число эпизодов
и общий ВЧ-уровень. Разные устройства не усредняются в одну характеристику.

## Паспорта A/B

Паспорт может использовать одну карту (`--dev`) либо раздельные ЦАП/АЦП (`--dac` и `--adc`).
Сначала сними эталон; затем — после изменения железа. Для строгого A/B сравнения сохраняй
одинаковую пару устройств и конфигурацию.

```bash
./run.sh cli --dac hw:3,0 --adc hw:2,0 --rate 192000 passport --quick --label before --out measurements/passport-before.json
./run.sh cli --dac hw:3,0 --adc hw:2,0 --rate 192000 passport --quick --label after --out measurements/passport-after.json --compare measurements/passport-before.json
```

Полный диагностический набор частот: `--rates diagnostic`; все объявленные распространённые
частоты: `--rates supported`. Для карты, ограниченной 48 кГц, используй `--rate 48000 --quick`
либо явный `--rates 48000`. Разные физические карты строго сравнивать как «до/после» нельзя;
`--allow-device-mismatch` только снимает блокировку и добавляет предупреждение.



После `steady` сохраняются:

- `summary.txt` и `steady.json` — сводка и машинно-читаемые результаты;
- `timeline.csv` — остаточная помеха и ультразвуковые полосы по 100-мс окнам;
- `tone-continuity.csv` — фактический уровень несущей в коротких окнах, независимо от остаточного шума;
- `capture-float32.wav` — исходная запись для последующего анализа.

Времена в CSV/JSON задаются по оси записи `arecord` (запись начинается до воспроизведения тестовой программы). При частоте тона ниже примерно 50 Гц короткий контроль несущей может быть помечен как недоступный: для достоверной амплитуды требуется не менее пяти периодов в одном окне.

## Обзор проекта

**ValveBench** — измерительная лаборатория для разработки и настройки аналоговых аудиотрактов, прежде всего ламповых фонокорректоров. Linux / Ubuntu, Python, GTK4 + Libadwaita, NumPy/SciPy, ALSA.

Это развиваемый инженерный инструмент, а не метрологически аттестованный анализатор. Синтетические тесты проверяют алгоритмы, но не доказывают точность физического измерения. Для оценки DUT сначала надо измерить собственный тракт ЦАП→АЦП, его шум, искажения, частотную характеристику и запас по уровню.

## 1. Установка и первый запуск

```bash
./install-deps.sh
./run.sh selftest
./run.sh debug
./run.sh
```

`install-deps.sh` устанавливает системные пакеты Ubuntu. Программа не использует Wine, Java, Electron или PortAudio. Аппаратный ввод/вывод реализован отдельными ALSA-процессами `aplay` и `arecord`.

`run.sh` предпочитает системный `/usr/bin/python3`, если в нём доступны NumPy, SciPy и GTK bindings. В противном случае использует `python3` из `PATH`. Явный интерпретатор задаётся переменной `VALVEBENCH_PYTHON`.

По умолчанию безопаснее начать с **«Симулятор (демо без карты)»**. Симулятор нужен для освоения интерфейса и проверки методик, но его цифры нельзя принимать за параметры реальной карты или устройства.

## 2. Главный экран и генератор

Верхняя кнопка **«АУДИОПОТОК: ОТКРЫТЬ / ЗАКРЫТЬ»** открывает или закрывает физические потоки ЦАП и АЦП. При включении аудио ЦАП сначала подаёт цифровую тишину, АЦП непрерывно измеряет вход.

На странице **Gain Match / Уровень** находится одна большая кнопка генератора:

- **«ПОДАТЬ ТЕСТОВЫЙ СИГНАЛ»** — начать выдачу заданного сигнала;
- **«ОСТАНОВИТЬ ТЕСТОВЫЙ СИГНАЛ»** — выключить сигнал, сохранив открытым измерительный аудиопоток.

Частота, уровень в dBFS и направление L+R/L/R задаются рядом. Это единственная кнопка управления генератором; отдельной дублирующей кнопки в заголовке нет.

Главный экран показывает два вертикальных RMS-индикатора L/R в одном масштабе, цифровые RMS, Peak, Peak Hold, запас до 0 dBFS, ADC CLIP и сообщения ALSA XRUN.

- **ADC CLIP** — цифровые отсчёты приблизились к full scale. Это не гарантирует обнаружение перегрузки аналогового входного каскада: аналоговая ступень может перегружаться раньше цифрового предела.
- **XRUN** — ALSA сообщила о playback underrun (ЦАП не получил данные вовремя) или capture overrun (приложение не успело читать АЦП). Это возможные пропуски/разрывы, не то же самое, что клиппинг.
- Нулевой счётчик XRUN означает, что соответствующих сообщений ALSA не получено. Это не заменяет прослушивание/контроль непрерывности и не является абсолютным доказательством отсутствия любых потерь.

Физические вольты и усиление появляются только после независимой калибровки каналов ЦАП и АЦП. До этого достоверны dBFS и относительные величины.

## 3. Большой спектр

Страница **«Спектр (большой экран)»** отделена от Gain Match. Она использует крупную область графика, логарифмическую шкалу частоты и настраиваемый вертикальный диапазон с частыми делениями.

Разрешение FFT: по умолчанию **256k** для лучшего частотного разрешения; 8k…128k доступны для более быстрого отклика. Выбранный размер сохраняется. Нижняя и верхняя границы dBFS для Спектра запоминаются отдельно для каждой физической карты и Fs.

Точный шаг `Δf = Fs/N`, эффективная полоса окна (ENBW), длительность окна и частота обновления отображаются под графиком. Увеличение FFT повышает разрешение по частоте, но делает отклик медленнее.

Диапазон частот можно выбрать в трёх вариантах:

- 20 Гц–20 кГц — обычная звуковая полоса;
- 10 Гц–40 кГц — расширенный обзор;
- 10 Гц–Fs/2 — весь положительный спектр до частоты Найквиста. Например, при 192 кГц отображается диапазон до 96 кГц.

Последний FFT-бин у чётного размера FFT расположен точно на Fs/2. На логарифмической оси 0 Гц не отображается; DC выводится отдельно в других приборах. Отображение за 20 кГц не означает, что аналоговый тракт карты имеет там нормированную АЧХ: это просто спектр того, что реально оцифровал АЦП.

Есть два разных способа отображения:

1. **Амплитуда линий, dBFS/bin** — удобно смотреть синусоидальные составляющие и гармоники. Высота шумовой полки на бин зависит от ширины бина и выбранного FFT.
2. **Плотность шума, dBFS/√Гц** — нормированная спектральная плотность. Она удобнее для сравнения шумовой полки при разных размерах FFT.

Это разные физические величины; нельзя сравнивать численные значения dBFS/bin и dBFS/√Гц напрямую. Для просмотра непрерывного шумового пола режим PSD выбран по умолчанию.

## 4. Измерительные приборы

- **Gain Match / Уровень** — два вертикальных RMS-индикатора L/R, Peak, Peak Hold, CLIP, живое ΔG и частотная серия усиления на 100 Гц / 1 кГц / 10 кГц. Серия выполняет заданное число повторов, выводит таблицу уровней L/R, ΔADC и (при полной калибровке ЦАП/АЦП) G(L), G(R), ΔG. В карточке можно указать устройство, лампы/позиции и примечание. JSON и CSV сохраняются в `./measurements/gain-match/` относительно каталога проекта; без калибровки программа явно показывает только разность уровней АЦП, не выдавая её за усиление. Текущая калибровка напряжения одноточечная: без отдельной частотной коррекции петли ЦАП/АЦП результаты на 100 Гц и 10 кГц включают АЧХ самой звуковой карты.
- **THD / THD+N** — гармоники H2…Hn, THD, THD+N и измерения в зависимости от уровня. THD и THD+N различаются: первое учитывает гармоники, второе — всё остаточное содержимое в заданной полосе кроме основной несущей.
- **АЧХ / RIAA / Sweep** — экспоненциальный свип, inverse-RIAA или плоский сигнал, отклонение от RIAA, фаза и оценка THD(f).
- **АЧХ шумом / H1** — белый, розовый или inverse-RIAA-shaped шум. Передаточная функция оценивается по известному сигналу ЦАП и записи АЦП (`H1 = Sxy/Sxx`); когерентность показывает, насколько выход связан с тестовым сигналом. Есть одноразовый и живой режимы. Это не просто FFT выхода.
- **IMD** — CCIF 19+20 кГц, SMPTE/DIN и настраиваемые пары тонов.
- **Шум / Crosstalk** — интегральный шум, A/C-взвешивание, спектральная плотность, сетевой фон и межканальное проникновение.
- **TACET / Vinyl Test** — анализ WAV-записей A2/A3/A4/A5/A6/A7 и частотной серии B2. Ограничения описаны в `docs/TACET.md`.

Шумовой H1-метод измеряет весь передаточный тракт: ЦАП, внешний аттенюатор/делитель, DUT, АЦП и соединения. Без калибровки петли ЦАП→АЦП нельзя отделить частотную характеристику звуковой карты от характеристики DUT.

## 5. Аппаратный loopback: основной диагностический тест

Для первого теста соедини **линейный выход ЦАП L/R напрямую с соответствующими линейными входами АЦП L/R**. Выбери на E-MU режим LINE и не используй Instrument/Hi-Z. Не подключай выход ЦАП к MM-входу фонокорректора. Сначала убедись, что уровень безопасен.

Останови живой режим в GUI, чтобы карта не оставалась занятой. Затем выполни команду (номер ALSA карты может отличаться; у E-MU в текущей тестовой системе это `hw:2,0`):

```bash
./run.sh cli --dev hw:2,0 --rate 96000 --blocks 2 loopback \
  --f 1000 --levels=-20,-30,-40 --repeats 2 --silence-seconds 3 \
  --report ~/valvebench-loopback-96k.txt \
  --csv ~/valvebench-loopback-96k.csv
```

Не добавляй `--sim`: эта команда должна измерять физическую петлю.

Тест:

1. Записывает шум до серии при одновременно открытых ЦАП и АЦП, когда ЦАП выдаёт цифровой ноль.
2. Проверяет отношение частот ЦАП/АЦП контрольным тоном 1 кГц.
3. Повторяет измерение тона на нескольких уровнях.
4. Считает уровни ADC, потери петли, THD, THD+N, остаток в dBFS, шум без гармоник, H2…H9, цифровой запас и повторяемость.
5. Для когерентного THD сравнивает каждую линию с широкополосным шумом в том же одном DFT-бине (с поправкой на усреднение блоков) и с устойчивыми узкополосными spur, обнаруженными в предварительной записи тишины на тех же бинах. Отдельно печатает широкую проверку шумового окружения ±5 Гц; она диагностическая и не является тем же порогом, что одно-биновое решение.
6. Повторно записывает тишину после серии, чтобы можно было увидеть изменение фона.

В отчёте `THD+N dBc` — остаток относительно измеренного основного тона; рядом выводится абсолютный остаток dBFS. Например, при основном тоне −25 dBFS и THD+N −85 dBc остаток будет примерно −110 dBFS. Это не означает шумовой пол −85 dBFS.

Запас ADC до цифрового full scale не доказывает отсутствия перегрузки аналогового входного каскада. Следи за режимом входа и его аналоговым уровнем.

## 6. Установка/калибровка

На вкладке Setup калибруются независимо:

1. DAC L и DAC R — мультиметром при известном тестовом уровне.
2. ADC L и ADC R — через проверенную петлю DAC→ADC.
3. Внешний аттенюатор/делитель указывается отдельно.

Калибровка входа и выхода в одной частотной точке не заменяет калибровку частотной характеристики всей карты. Для точного измерения DUT потребуется отдельный loop-профиль по частоте и оценка остаточных THD/IMD самого измерительного тракта.

## 7. Текстовая диагностика вместо скриншотов

Основная команда:

```bash
./run.sh debug
```

Короткий отчёт без DSP self-test:

```bash
./run.sh debug --no-selftest
```

Сохранить текстовый отчёт:

```bash
./run.sh debug --save
```

Если проблема проявляется при открытии окна или работе интерфейса:

```bash

```

`debug` не открывает и не закрывает аудиоустройства и не генерирует звук. Он показывает возможности карт, активные ALSA `hw_params`, выбранную конфигурацию и состояние модулей. Для проверки потока `hw_params` нужно читать, пока аудио включено.

## 8. Известные ограничения

- Самотесты проверяют математику и виртуальный DUT, но не аналоговые характеристики E-MU или другого интерфейса.
- У пользователя подтверждено, что E-MU 0404 USB открывает playback и capture одновременно в `S24_3LE`, 2 канала, 96 кГц. Это подтверждает параметры PCM-потоков, но ещё не точность измерения THD/шумов реальной петли.
- Аппаратный loopback-тест нужно выполнить на своей карте. Уровни THD/THD+N карты ещё не следует считать откалиброванными.
- XRUN счётчик основан на сообщениях ALSA stderr. Ноль сообщений — хороший признак, но не абсолютное доказательство отсутствия любых сбоев.
- `ADC CLIP` ловит цифровое приближение отсчётов к full scale, но не гарантирует обнаружение аналоговой перегрузки.
- TACET-анализ выполняется по записанному WAV и не является сертифицированной оценкой проигрывателя, картриджа или тонарма. Для A2 сейчас выдаётся оценка нестабильности 3150 Гц, а не стандартизованный DIN/IEC Wow & Flutter. Для B2 распознаётся серия частот, но точные заводские уровни и допуски дорожки не предоставлены.
- LP-тест включает проигрыватель, картридж, тонарм, кабель, фонокорректор и ADC; результат нельзя автоматически приписать одному фонокорректору.

## 0.1.5: coherent harmonic analysis

Когерентное измерение фазонормирует комплексные гармоники по фазе фундаментального тона каждого блока; смотрите `phase coherence` в отчёте. Если линии ниже порога, THD не выдаётся как точное значение: см. `THD detected lines` / `raw harmonic-bin sum`. Порог когерентной линии — 10 dB над суммой оценки случайного однобинового шума (с поправкой на число блоков) и устойчивого spur, найденного в предварительной записи тишины. Это инженерная классификация, а не метрологическая неопределённость.


## 0.1.5 — coherent harmonic floor and Gain Match validation

The coherent THD estimator phase-normalizes harmonic phasors per block. It uses a
one-bin broadband noise estimate from neighbouring bins and an additional silent-input
profile for stable coherent spurs at the exact harmonic bins. These floors are combined
before a line is marked as detected. The wider ±5 Hz silence comparison remains a
separate diagnostic and is not the same bandwidth as the coherent single-bin decision.

Run the deterministic software checks with `./run.sh selftest`. For the E-MU hardware
loopback, use the direct ALSA `hw:2,0` line-output-to-line-input connection and compare
repeated results; do not treat simulator values as physical measurements.



## Gain Match: измерение баланса каналов усилителя

Режим работает в два шага и не требует калибровки вольтметром для сравнения L/R:

1. **Измерить петлю карты** — напрямую соединить DAC L→ADC L и DAC R→ADC R. Программа запоминает собственную разницу каналов измерительной карты отдельно на 100 Гц, 1 кГц и 10 кГц.
2. **Измерить усилитель** — включить устройство в измерительный тракт. Программа вычитает соответствующую частотную поправку петли и показывает только полезный результат: `ΔG = G(L) − G(R)`, повторяемость и вердикт по допуску.

Эталон действует только в текущем сеансе приложения. После перезапуска, переподключения карты, изменения частоты дискретизации, уровня генератора или микшера шаг 1 нужно выполнить заново. Между шагами приложение сравнивает снимок `amixer contents` и блокирует измерение, если настройки карты изменились. Файл эталона сохраняется в `measurements/gain-match/` для истории.

Поправка компенсирует асимметрию ЦАП/АЦП карты. Она не исправляет различия внешних кабелей и аттенюаторов: их L/R-плечи должны быть согласованы, а настройки между двумя шагами нельзя менять. Относительная разница усиления L/R доступна без абсолютной калибровки напряжения; абсолютные `G(L)` и `G(R)` требуют отдельной калибровки вольтметром.
