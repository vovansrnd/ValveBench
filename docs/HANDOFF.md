## 1. Проект и роли

**Продукт**: ValveBench — измерительная лаборатория для аналоговой аудиотехники
(GTK4/CLI, ALSA): steady (длительный matched-level тест ЦАП→АЦП), Gain Match,
passport, THD/IMD, АЧХ, TACET/Vinyl, selftest. Пользователь — владельец,
мастерит ламповые фонокорректоры, работает в Linux.

**Схема работы** (введена новым координатором):
| Направление | Ответственный |
|---|---|
| Архитектура, продуктовые решения, версии, changelog, интеграция | Координатор (человек) |
| Аудит математических методов | Координатор + агент |
| DSP, синтетические испытания | Совместно |
| ALSA, физические карты, реальные прогоны, GTK smoke-тесты | **Агент** |
| Проверка патчей агента | Координатор |

Правила координатора: одно подсистемное изменение = отдельное задание с явными
критериями приёмки; выводы агента — с доказательствами (код/тесты/логи/замеры);
не смешивать исправление алгоритмов, новую функциональность и рефакторинг;
новая функциональность — только после приёмки предыдущего этапа.

**Мой статус на момент передачи**: P0 и P1 приняты координатором как контрольные
точки; 0.1.18 принята как исправление интерфейса; ожидаются: (а) независимая
математическая проверка будущих выводов координатора по Gain Match, (б) синтетические
тесты с известными значениями, (в) NOTHING else until the coordinator assigns.

## 3. Что проверено (сводка верификации)

### Ядро измерений (steady/pcm/io_health)
- Независимый аудит (AUDIT-STEADY-0.1.11.md, ревизии 1–13, в корне for_z):
  математика steady корректна (Parseval, Найквист-бин, LS-проекция, частотный фит,
  per-state частоты); P0 — memory-safe (2472→365 МБ на 192к/124с, бит-в-бит
  равенство метрик); P1 — io_health (XRUN/длина/onset/validity_reasons), дефект
  прокрутки опровергнут корректным замером.
- Selftest 0.1.18: 71/71 (включая P0/P1-чеки). Независимый набор: 38/38.

### Аппаратные кампании (16 реальных прогонов)
- E-MU 176,4/192 кГц аномалия: broadband-всплески на L при активном L-тоне
  (fingerprint: 40–50 кГц +31 дБ, гармоники целы, несущая цела; 68–167/395 окон,
  сессионно-прерывистая; источник — тракт воспроизведения E-MU, не её АЦП).
- ASUS: всплесковый шумовой пол (экскурсии 103–138 окон) — свойство карты;
  **2 реальных пропадания несущей** (54.60–54.67 и 55.10–55.17 с, по 84 мс,
  до −115 дБ) — записаны 06.11 в HW3, с тех пор не воспроизводились.
- Уровень ASUS: дефолт после replug = **234** (подтверждено), пользователь
  обычно ставит **253** («100 и шаг назад», 0,5 дБ/шаг) — разница ровно 9,5 дБ.
  Изменение пола L (−97,4→−110,1) громкостью не объясняется — отдельная
  особенность. Входные регуляторы: Capture Source = Mic, Input Gain Pad 2/2,
  Line off — фиксируются процедурой hw_prepare.py.

### P1 io_health — финальная верификация (GUI smoke v4, 9/9)
Все проверки из ТЗ координатора: строгие состояния аудиотракта; точность
отклонения уровня (14,0 дБ ± 0,5); стабильность L при маршруте (0,00 дБ);
фактическая частота по захваченному сигналу (500,0/1000,0 Гц); максимум
прокрутки и нижний контент на всех 9 страницах (в системе координат скроллера).

### USB integrity audit ASUS (закрыт координатором)
- usbmon 1t (793 516 строк): статусы чистые, каденция нормальная, провалов
  сервиса в момент dropouts нет, ECONNRESET только на закрытии потоков.
- **Ограничение: 1t не показывает per-packet iso-ошибки** (error_count — только
  в 1u; подтверждено исходником mon_text.c). При естественном повторении
  явления — 1u-захват.
- Переделка PCIe→USB (ручная пайка D+/D− ~3 см, скрутка, без экрана) —
  гипотеза причины, не доказана. Документация: CM6632A datasheet v1.1
  (встроенный PHY, LQFP 100, D−=выв. 5, D+=выв. 6 — по прочтению координатора),
  семейные layout-гайды CM6646/CM6533 (90 Ом ±15%, без stubs, непрерывная
  земля). 22 Ом — снят со списка (в документах не требуются). «212» = 2,1 кОм
  по стандартному коду, принадлежность USB-линии не установлена.

## 4. Окружение — специфика (ВАЖНО, читай внимательно)

### Десктоп
- **Wayland, композитор Umbriel + shell Noctalia** (НЕ GNOME!). Тайлинг:
  scrolling layout, новое окно на занятом столе встаёт на ~2/3 (extent-пресеты
  0.333/0.5/0.667). На свободном воркспейсе — полная рабочая область.
- **GUI-прогоны агента**: запускать на СВОБОДНОМ воркспейсе через IPC:
  `umbriel msg workspace-switch 9` → spawn → окно встанет там → вернуться на
  воркспейс пользователя. Не трогать раскладку пользователя.
- **Скриншоты**: `noctalia msg screenshot-fullscreen` — работает, сохраняет в
  `~/Pictures/` (шаблон `20261106_21h33m43s_grim.png`). ПЕРВЫЙ вызов открывает
  интерактивный оверлей — последующие работают без него; при зависании оверлея
  пользователь жмёт Esc. НЕ использовать: gnome-screenshot (зависает на
  Wayland), org.gnome.Shell.Screenshot dbus (ServiceUnknown), import/Xvfb
  (конфликт), GTK Widget.snapshot (не интроспектируется в PyGObject).
- grim/slurp установлены — запасной независимый путь.

### Командная строка агента (footguns, на которых я спотыкался)
1. **pkill -f убивает собственную команду**, если паттерн встречается в её же
   командной строке (в т.ч. в других частях составной команды). Три раза
   положил собственный bash. Никаких pkill в составных командах с gui_smoke.
2. **Фоновые процессы умирают между вызовами Bash-инструмента** (Xvfb,
   драйверы) — всё, что нужно живым, делай в ОДНОЙ команде.
3. **cwd сбрасывается между вызовами** — всегда `cd` в той же команде или
   абсолютные пути.
4. **SIGTERM при timeout убивает буфер stdout** — для диагностики зависаний
   используй `python3 -u` и/или файловые метки внутри процесса.
5. Свободная RAM ~1,4–3,5 ГиБ (машина 7,1 ГиБ) — тяжёлые замеры под
   `systemd-run --user --scope -p MemoryMax=3G`, чтобы не убить приложения
   пользователя. После P0 полный конвейер занимает ~360 МБ — теперь безопасно.
6. sudo требует пароль; pkexec работает (GUI-диалог) — usbmon загружался им.

### ALSA
- Номера карт меняются после переподключения. Идентификация по USB VID:PID:
  `/proc/asound/card*/usbid` (E-MU = 041e:3f04, ASUS = 0b05:180c).
  **hw_prepare.py** (audit-steady/) делает всё автоматически: идентификация,
  снимки amixer до/после, установка FL/FR = 253, контрольное чтение,
  перечень входных регуляторов. Запускать ПЕРЕД каждым аппаратным прогоном.
- Микшер ASUS после replug: FL/FR = 234 (дефолт) — пользователь обычно 253.
- **E-MU сейчас ОТКЛЮЧЕНА пользователем** (только ASUS в порту 1-2, card 2).
  Попроси пользователя подключить, когда понадобится.

## 6. Следующий этап (по координатору) — аудит Gain Match

Координатор проводит свой аудит; роль агента — независимая математическая
проверка его выводов и синтетические тесты. Известные вопросы (от
координатора, ревизия 13):
1. Достоверность: связать Reference → DUT с критериями P1 (XRUN/неполный
   захват/ненадёжный onset → не допускать ложных заключений).
2. TARE: обнуление переживает смену частоты генератора — привязать ноль
   к условиям измерения (возможно, опорные значения на частоту).
3. Математика: `-thdn_db` под именем SNR — математически это SINAD;
   разделить SNR/SINAD/THD+N, правильные наименования и критерии.
4. Отображение L/R и сохранение измерений.

Мой вклад (уже сделан, пригодится): в 0.1.14/0.1.16 уже реализованы
микшер-хеш и VID:PID-идентификация (те же принципы, что у нас в P1/hw_prepare).
