# Паспорта измерений DUT в ValveBench 0.1.21-dev1

## Назначение

Функция сохраняет отдельный завершённый результат измерения проверяемого устройства (DUT) под его инвентарным номером: `590`, `591` и т. п. Это первая ступень будущего импорта и сравнения измерений. Она не меняет существующий `passport` звуковой карты: тот по-прежнему диагностирует тракт ЦАП/АЦП.

## Как сохранить результат

1. В верхней панели ValveBench введи номер устройства в поле **«№ аппарата»**. Допустимы латинские буквы, цифры, точка, дефис и подчёркивание; длина — до 64 символов. Примеры: `590`, `591`, `PHONO-590`.
2. В поле **«лампы / заметка»** можно указать типы и позиции ламп, состояние аппарата или особые условия.
3. Введи ID до начала теста. Выполни измерение на любой странице и дождись завершения. Кнопка **«СОХРАНИТЬ ЗАМЕР»** становится активной, когда есть результат и заполнен ID. ID фиксируется в контексте при запуске измерения: если после теста поменять его на другой, сохранение будет остановлено, чтобы не приписать результат другому аппарату.
4. Нажми кнопку сохранения. Каждый клик сохраняет отдельную неизменяемую сессию. Повторные измерения одного аппарата не затирают предыдущие.
5. Для другого устройства измени ID перед сохранением его результата.

Сохраняется именно последний завершённый результат. Например, после измерения АЧХ, затем THD нужно нажать «СОХРАНИТЬ ЗАМЕР» после каждого измерения, если нужны оба результата.

## Где лежат файлы

По умолчанию результаты находятся в каталоге активной копии ValveBench, независимо от того, откуда приложение было запущено (терминал, ярлык или рабочий стол):

```text
measurements/
└── devices/
    ├── 590/
    │   ├── 20261110-142500-sweep/
    │   │   ├── session.json
    │   │   ├── metrics.csv
    │   │   ├── curves.csv
    │   │   ├── MANIFEST.json
    │   │   └── README.txt
    │   └── 20261110-143100-thd/
    └── 591/
        └── 20261110-151000-sweep/
```

Имена каталогов включают локальную дату/время и тип результата. При совпадении времени добавляется числовой суффикс. Программа не перезаписывает существующую сессию.

## Содержимое сессии

- `session.json` — главный полный документ: ID, дата/время, заметка, тип теста, контекст измерения и исходная структура результата вместе с числовыми массивами.
- `metrics.csv` — плоский список скалярных метрик и параметров для таблиц.
- `curves.csv` — длинный CSV с колонками `group`, `x_name`, `x_value`, `series`, `y_value`. Подходит для импорта в LibreOffice Calc, Python/pandas и другие анализаторы. Неопределённые точки записываются пустыми ячейками.
- `MANIFEST.json` — размеры и SHA-256 каждого из четырёх файлов выше. Нужен для проверки целостности после копирования.
- `README.txt` — краткое описание комплекта.

JSON является источником истины. CSV — производные удобные представления. В контексте сохраняются версия ValveBench, профиль сборки, звуковая карта/устойчивый ID, ALSA PCM, sample rate, формат и канальность потоков, снимок идентичности ALSA mixer, калибровки DAC/ADC, коэффициент PAD DUT→ADC, маршрутизация каналов и анализируемая полоса.

Общие функции измерения пока не сохраняют необработанный непрерывный PCM для каждого теста. Если конкретный результат сам содержит аудиоданные, они попадут в JSON; в остальных случаях сохраняются исходные численные данные анализа и кривые. Запись исходного WAV для каждого типа теста — отдельная следующая задача.

## Передача результатов

Для передачи одного аппарата скопируй целиком каталог `measurements/devices/590/` либо выбери нужную датированную сессию. Не отправляй только CSV: для полноценного повторного анализа нужен `session.json` и весь комплект. Если каталог установки ValveBench недоступен для записи, сохранение сообщит ошибку; не следует молча подменять его каталогом в домашней папке — выбери рабочую копию в каталоге, куда у тебя есть права записи.

Проверка SHA-256 на Linux из каталога сессии:

```bash
python3 - <<'PY'
import hashlib, json, pathlib
p = pathlib.Path('.')
manifest = json.loads((p / 'MANIFEST.json').read_text(encoding='utf-8'))
for name, meta in manifest['files'].items():
    data = (p / name).read_bytes()
    digest = hashlib.sha256(data).hexdigest()
    ok = digest == meta['sha256'] and len(data) == meta['size_bytes']
    print(('OK  ' if ok else 'FAIL'), name)
    if not ok:
        raise SystemExit(1)
PY
```

## Что не следует терять

- Не меняй файлы в уже сохранённой сессии вручную: это нарушит MANIFEST.
- При повторной обработке оставляй исходную сессию нетронутой и сохраняй новый результат отдельной сессией.
- Для сравнения двух аппаратов должны совпадать тестовая методика, уровень сигнала на входе DUT, калибровка и конфигурация тракта. Если что-то отличается, это обязательно должно быть записано в заметке/условиях.
- Текущий экспорт не выполняет A/B-сравнение и не импортирует JSON в приложение; такой интерфейс — следующий этап.
