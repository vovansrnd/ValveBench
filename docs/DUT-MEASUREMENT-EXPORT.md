# Пакетные паспорта измерений DUT в ValveBench 0.1.21-dev2

## Быстрый порядок работы

1. Открой в боковой панели **«Пакетный замер DUT»**.
2. Введи номер аппарата (`590`, `591` и т. п.) и заметку о лампах/состоянии.
3. По умолчанию выбраны **АЧХ, THD/THD+N и шум**. IMD 19+20 кГц можно добавить.
4. Параметры конкретных тестов берутся с одноимённых страниц **АЧХ**, **THD**, **Шум** и **IMD**. Если нужны не заводские значения, заранее выставь их там.
5. Нажми **«ВЫПОЛНИТЬ ПАКЕТ ИЗМЕРЕНИЙ»**.
6. Если выбран шум, он идёт первым. На входе DUT в этот момент должна быть именно та нагрузка/терминация, для которой ты хочешь получить шум. После измерения пакет остановится и попросит подключить Anti-RIAA. Переподключи тракт и нажми **«ПОДКЛЮЧИЛ ANTI-RIAA · ПРОДОЛЖИТЬ»**.
7. После завершения нажми **«СОХРАНИТЬ ВЕСЬ ПАКЕТ»** один раз. Все выбранные результаты, параметры и общий контекст сохранятся одной сессией. Если часть тестов завершилась ошибкой, успешную часть можно сохранить отдельно со статусом `partial`.

Если для отдельной диагностики нужен только один тест, сними остальные галочки и запусти пакет с одним выбранным тестом. Так сохранение всё равно будет единообразным.

## Что сохраняется

Для каждого сохранения создаётся новая неизменяемая сессия в каталоге активной копии ValveBench:

```text
measurements/devices/<ID>/<timestamp>-dut_batch/
```

В ней находятся:

- `session.json` — полные результаты, вложенные тесты и численные массивы, параметры, временные метки, заметка и контекст измерительной карты;
- `metrics.csv` — плоские скалярные метрики и параметры;
- `curves.csv` — численные массивы кривых в длинном формате, пригодном для Calc/Python;
- `MANIFEST.json` — SHA-256 и размеры файлов;
- `README.txt` — описание сессии.

JSON — первичный источник истины. CSV — удобные представления для таблиц и анализа. Исходный WAV/PCM для каждого теста пока не записывается; сохраняются полные численные результаты, которые возвращают анализаторы.

## Контекст и целостность

В сессии фиксируются версия приложения, локальные дата/время, выбранная карта, устойчивый ID устройства, ALSA PCM, частота дискретизации, формат и число каналов, настройки микшера (fingerprint), калибровки ЦАП/АЦП и введённая поправка PAD DUT→ADC.

ID аппарата и заметка берутся на момент старта измерения. Если ID поменять до сохранения, ValveBench не позволит тихо записать результат под другим номером. Изменение заметки после завершения также не переписывает заметку, зафиксированную на старте.

Новая сессия не затирает предыдущую. Для передачи аппарата скопируй всю папку `measurements/devices/<ID>/` или нужную сессию целиком. Не отправляй только CSV: для анализа нужен `session.json` и MANIFEST.

## Сравнение нескольких аппаратов

После измерений можно сравнить две или более сохранённые сессии из командной строки:

```bash
SESSION_590="measurements/devices/590/20261112-101500-dut_batch"
SESSION_591="measurements/devices/591/20261112-103000-dut_batch"
./run.sh cli dut-compare "$SESSION_590" "$SESSION_591"
```

Вместо каталога можно передать прямой путь к `session.json`. Результат сохраняется в `measurements/comparisons/<timestamp>-dut-comparison/`:

- `comparison.json` — полное сравнение;
- `metrics.csv` — скалярные показатели с отдельными L, R и агрегатом;
- `curves.csv` — частотные кривые АЧХ с отдельными L, R и агрегатом.

Сравнение намеренно отклоняет пакеты с разными ЦАП/АЦП, Fs, форматами, микшером, калибровкой, набором тестов или параметрами. Для dB-показателей агрегат считается в области мощности; для процентных искажений — RMS по каналам. L/R всегда остаются отдельными колонками. Можно сравнивать и две разные сессии одного ID (например, до/после модификации).

В GUI также есть отдельная страница **«Сравнение DUT»**: обнови список, отметь минимум две завершённые сессии и нажми «Сравнить выбранные сессии». Сравнение выполняется без открытия звуковых устройств и сохраняется в ту же папку `measurements/comparisons/`. Выбор/сравнение также доступно через CLI.

Если в пакетах есть АЧХ, на странице строится наложение полных кривых: цвет — аппарат, сплошная линия — L, пунктир — R. Агрегированные значения по каналам остаются в текстовой сводке и CSV; график не заменяет раздельные L/R.

## Пока не реализовано

- Сохранение необработанного WAV/PCM во всех режимах.
- Автоматическое переключение аналоговой нагрузки/Anti-RIAA: после шумового теста физическое переподключение выполняет оператор.
